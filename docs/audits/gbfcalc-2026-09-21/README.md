# gbfcalc.com 比較監査(2026-09-21)

## 結論

gbfcalcは「公開データを選択可能な編成へ落とし込み、相対比較する」点でgbfHelperの計算機に近い。特に寄与内訳、テンプレート、保存編成の比較、結果付近の制約説明は参考になる。一方、gbfHelperは実機検証履歴・出典品質・未対応効果をデータ単位で追跡できることを差別化の中心に置く。

調査対象: [gbfcalc.com](https://gbfcalc.com/)、[使い方ガイド](https://gbfcalc.com/guide)、[計算式の説明](https://gbfcalc.com/formula)、[実装データ一覧](https://gbfcalc.com/data)。数値データの転記は行っていない。

## ワークフロー監査

| 手順 | 観察 | 健全性 |
| --- | --- | --- |
| 1. 初期状態 | 空編成に「テンプレ編成を入れる」があり、初回でも試算へ進みやすい | 良好 |
| 2. 武器選択 | 属性・武器種・シリーズ・枠・検索・並び順、件数表示がある。検索はスキル名にも対応 | 良好。ただし長大リストと小さい文字は改善余地 |
| 3. 編成調整 | 凸・SLv・覚醒を武器単位で指定し、未解放スキルも警告する | 良好 |
| 4. 集計確認 | Ω・EX・通常、HP、技巧、連撃などを即時集計し、武器別の寄与元を展開できる | とても良好 |
| 5. 試算 | 攻撃カテゴリと前提条件を指定し、結果・乱数幅・内訳を表示する | 良好。相対値であることを結果面でもさらに強調できる |
| 6. 比較・共有 | 保存編成の一括比較、ローカル保存、URL共有がある | 良好 |
| 7. 出典確認 | 計算式・実装一覧・未実装理由を公開している | 良好。ただし「確認済」の根拠粒度は項目ごとにばらつく |

## 取り入れる価値が高い点

1. **寄与内訳の標準化**: 合計値だけでなく、武器・スキル・枠・加護前後の寄与を常に返す。gbfHelperでは既存のdiagnostics/provenanceをUIとWebMCP返却へ一貫して露出する。
2. **テンプレートと空状態の導線**: 検証済みの最小編成をワンクリックで読み込み、計算結果まで到達できるようにする。
3. **結果付近の制約説明**: `未対応`、`二次情報`、`実機検証済み`を結果の近くに表示し、0として扱った効果と未実装を区別する。
4. **保存編成の同条件比較**: 同じ敵・HP・ターン条件で複数編成を比較する。入力条件の差を混ぜない。
5. **フィルタ状態の保持**: 属性・武器種・シリーズ・枠を保持し、連続登録を速くする。

## gbfHelperで優先する差別化

- 各数値に`verificationStatus`、出典、確認日、実機検証ケースを持たせる。
- 未対応効果を黙って0にせず、`unsupportedEffects`と結果警告に残す。
- 計算結果からナレッジと検証ノートへ逆引きできるようにする。
- gbfcalcのデータセットや画像は転用せず、海外Wiki・攻略サイト・ユーザー提供の実機データを独立した出典として扱う。

## アクセシビリティ・性能上の注意

- ダーク背景上の小さい灰色・青緑文字はコントラストと可読性の確認が必要。
- 枠色やバッジ色だけに意味を依存せず、短いテキストラベルを併記する。
- 500件超の選択肢を一度にDOMへ出さず、検索・ページング・仮想化とスクリーンリーダーの両立を確認する。
- 検索欄やコンパクトなselectには可視ラベルと十分なタップ領域を持たせる。
