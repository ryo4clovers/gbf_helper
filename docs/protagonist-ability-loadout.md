# 主人公アビリティ編成の対応範囲

2026-10-05実装。全80ジョブの編成選択に対応する。戦闘効果の全アビリティ実装を意味しない。

## 保存と装備判定

`deckConfig.protagonist.abilityIds` は自由枠の順序配列。値は既存カタログのaction ID文字列、空き枠は`null`。固定枠は保存せずジョブMarkdownから派生する。ClassIは固定2＋自由1、ClassII/III/EXIは固定3＋自由1、それ以外は固定1＋自由3。

旧編成・旧名前付き編成にフィールドがない場合は空の自由枠へ移行する。ジョブ/育成段階のUI変更では有効選択と位置を保持し、無効になった選択だけを外す。JSON入力は重複・候補外ID・自由枠/カテゴリ上限超過・判明した当該ジョブLv/極致条件を拒否する。APIも同じ判定を使う。

固定2/3枠の習得LvはMarkdownに明記された値を使い、未到達は表示する。習得元ジョブのLvや極致、EMPによる習得済み状態は編成データにない。そのため候補の表示はユーザー本人の習得保証ではない。これら未管理条件は明示し、現在のジョブLvや現在の極致を継承元の条件へ誤適用しない。

## 既存データと不足範囲

- 固定枠: `knowledge/jobs/` の全80件の「アビリティ構成」見出し。固定枠数の根拠は `knowledge/mechanics/abilities.md`。名称に書かれた習得Lv以外を推測しない。レベル/MLによる全強化版への名称切替は未対応。
- 自由候補: `knowledge/abilities/free-slot-candidates.json` の309アビリティ、77ジョブの候補ID/EX・リミット・ベース種別/カテゴリ上限。元資料はユーザーの通常操作で得られた観測から匿名化済み、取得日2026-09-06〜07。ローカル原本は読み込まない。知識データの「下書き」を維持する。
- 未観測3ジョブ: ClassI版ファイター/ランサー/ウィザード。既存mechanicsに記載された系列リミット規則に基づき同系列ClassIIのリミット候補を再利用する。EXは既存60種の共通プールから本人の固定アビ相当の名称を除外する。直接観測と区別して「導出・候補一覧未観測」と表示する。完全な全アカウント習得プールとは断定しない。
- ClassI自由1枠は既存資料でも要再検証が残る。暫定枠構成として表示する。
- 新ジョブ、未収録アビリティ、記録外の習得条件や排他関係は追加しない。同名に似ている/同色/同じ効果という理由で独自の相互排他を作らない。

## 公開資料による補足（clover調査、参照2026-10-05）

Originのリミット枠上限は初期2。Fighter/LancerはLv30、WizardはLv40で3へ増える。個別のLevel Bonusesを優先し、Class Skills集約表から一律のLvを推定しない。

- https://gbf.wiki/Fighter_Origin#Level_Bonuses
- https://gbf.wiki/Lancer_Origin#Level_Bonuses
- https://gbf.wiki/Wizard_Origin#Level_Bonuses
- https://gbf.wiki/Classes （クラス別固定/自由枠）
- https://gbf.wiki/Ultimate_Mastery （極致はEM枠、習得元本人・対応Originのみ、ClassVへ引継がない）

公開Wikiは二次資料。今回の補足Lv規則は実機未再検証。知識のステータスを検証済みに変更しない。回帰テストは採用したソフトウェア仕様の確認であり、ゲーム全条件の実測保証ではない。

## 戦闘側

編成画面から戦闘へ渡した自由枠を使い、戦闘内で別途装備し直すチェック欄はなくす。全ジョブの固定/自由枠を同じ順序で表示し、未装備/未実装は実行ボタンを無効にする。

既存のLv50ファイター・オリジン行動処理へは `202071`（ファング）、`200721`（ウールヴ）、`203961`（アンリミ）を接続する。固定WBは既存処理。状態・発動のみ対応、数値効果未計算という既存の範囲を維持する。他ジョブの同アビを戦闘対応扱いにしない。使えない理由（ゲージ100%、闘心Lv5、使用済み、再使用待ち、ウールヴ中手動不可）を表示する。未装備ファングの手動/通常後自動発動を禁止する。

APIの旧 `fighterLoadout` は互換入力として残る。新しい編成側の `abilityIds` がある場合は編成が正本で、旧入力の不一致と継続状態の装備不一致を拒否する。戦闘保存と履歴も同様。単発通常ダメージ画面の既存アーマーブレイク予測等は比較用計算であり、装備や実行を表すものではない。

Fang数値計算は並行する別タスクで、今回の差分には含まれない。統合時はAPIの `generated.protagonistCalculation` を敵行動直前の結果として優先する処理を保持する。Fangイベントに減衰前参照値の契約がある場合のみ「条件付き効果対応・減衰後ダメージ未計算」と表示し、その参照値をHPダメージには加算しない。

旧戦闘保存のsetupキーと復元先setupは、欠落した `abilityIds` のみ空配列へ移行して照合する。旧未装備保存は復元できるが、実際の装備・ジョブ・Lv・選択順の不一致や破損保存は拒否する。nullや不正な型を空装備へ修復しない。
