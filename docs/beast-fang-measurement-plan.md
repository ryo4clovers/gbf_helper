# ビーストファング実装と最小計測計画

作業基点: `ef5c2e9b7fa5b8dd918f532cf25b1bd2d9b6adcc`。
公開情報の参照日: 2026-10-05（cloverからの出典確認を引継ぎ）。
出典: [Berserker oldid=1004023](https://gbf.wiki/index.php?title=Berserker&oldid=1004023)、更新2026-07-03。
4倍・概算上限63.5万・片面攻防25%DOWN/180秒・自己全上限50%UP/2T・延長不可・CT7は
GameWith由来の公開二次情報であり、実機確定値とは区別する。
実装環境のWebツールではこの固定版を再取得できなかった。引継ぎ済みの確認以上の独立検証は主張しない。

## 接続範囲と未確定

- `beastFangDamage.ts` → `calculateProfileDamage` を使用し、手動/ウールヴ/無窮の各発動に
  `preAttenuationDamage` を返す。4倍、主人公アビLB/コンプリート、武器アビ補正、闘心レベル、
  HP依存基礎・属性相性・確定武器技巧は既存経路へ接続する。
- この参照値は減衰・減衰後増幅・固定与ダメージ・最終丸めを含まない。
  `damage:null`/`calculationStatus:未計算` を保持し、Web敵HPへ加算しない。
  既存標準減衰表は通常/反撃・奥義・チェイン用で、Fangに共用する根拠はない。
  63.5万から4ラインを逆算せず、hard clampも行わない。
- `calculation.beastFangDebuffHit` は今回の発動（自動時は当該ターンの各発動）の命中観測または
  明示シナリオ。`true`のみ攻防25%を付与。`false`/省略は既存弱体を消さず、新規数値付与を行わない。
  未指定はイベントに`debuffOutcome:unknown`を返す。自動94発の命中を一括で実測確認した扱いにしない。
  一括行動生成の固定条件では`automaticAbilityConditions.beastFangDebuffHit`を同じ意味で受け取り、
  当該生成範囲の各Fangへ渡す。固定条件の`characters`配列はFang計算要求へ渡さない。
- 弱体期限は`fangDebuffExpiresAt`に秒で保存し、各ターン開始の`elapsedSeconds`で比較する。
  ターン内0秒という既存モデルの制約を維持する。180秒を固定ターン数へ変換しない。
- 枠不明の既存防御DOWNとFang片面25%は最大値を選ぶ暫定の非加算モデル。
  別枠なら過小評価になるため警告する。既存モデルの一般防御DOWN下限50%/下限突破枠を利用するが、
  枠競合を正確に解決した扱いにしない。攻DOWNもイルザ25%との共存は最大25%に留め、枠競合未確認。
- 自己上限50%は他の一般上限バフと最大値を選び、味方には付与しない。
  発動ターンを含む2Tを`fangCapExpiresOnTurn = turn + 2`で追跡。
  再付与で期限を更新する仮定を明記する。「延長不可」から再付与可能性を実測確定と解釈しない。
  強化延長操作は実装していない。状態の旧observedフラグだけから有効期限を復元しない。
- 1発目ダメージ参照→弱体→自己上限、2発目には更新後の状態を使う。
  共存トリガーの内部順はウールヴ→無窮だが、発動元の先後はログから識別不能。
- 無窮奥義倍率、無窮の数値強化、ウールヴ追撃、カウンター倍率は今回未接続。
  それらと共存した値をFangの倍率/上限へ吸収しない。

## 優先1: Fang自身の減衰設定と4倍

最小で、Fangを含むジョブアビ詳細のレスポンスを1件。レスポンスに含まれる場合は
公開アビID/効果文、`damage_limit_type`、`damage_limit1`〜`4`、`damage_deduction1`〜`4`、
倍率・hit数・攻防DOWN・上限効果量と期限を保存する。存在しないフィールドは取得済みとしない。
この設定があれば63.5万の候補表は不要になる。

倍率照合はLv50オリファイ、Fangのみ、同じ敵・HP・装備で低火力のFangを3発から開始。
WB/ウールヴ/アンリミ/無窮/他アビ/召喚を使わず、他の自動アビやバフを持たない前衛または主人公単独。
技巧/クリティカル、与ダメージ加算、上限UP、追撃、開幕アーティファクト、時間変化する強化を外す。
外せない補正は種類・量・適用時点を保存し、0と仮定しない。
Fangの弱体/上限が消えた状態から各発を取り、Fang後の通常値をFang前基礎と混同しない。
共通基礎算出用の通常攻撃も効果なしの同条件で1ターン（可能ならDA/TA）保存する。
闘心Lvを揃え、途中Lv変化があれば別条件に分ける。

設定取得不可でも優先1は自己上限なしの低火力3発だけから始め、中間減衰ラインは確定しない。
手動FangはCT7、自己上限は2Tなので、Fangのみの条件では上限効果中に次の手動Fangを使えない。
再使用可能になるまで待つ場合も弱体180秒の失効と自己上限2Tの失効を状態で確認する。
上限ありのFangは優先2の自動発動条件で別に観測する。

保存: 編成/主人公Lv・LB・コンプリート/武器・召喚/HP、戦闘開始レスポンス、
Fang使用レスポンス、直前/直後の主人公・敵の状態、攻撃ターンレスポンス。
敵防御値はレスポンスから自動確定した扱いにせず、既知条件/未確認入力として記録する。

## 優先2: 自己上限再付与と連続2発

ウールヴだけで通常後Fangを1発、次ターンも1発取り、付与直後・次ターン開始・
追加発動直後の自己上限状態と残り期限を保存する。2T更新か、更新拒否かを確認する。
自動を止めて2ターン経過させ、失効境界も保存。延長操作とは区別する。

減衰設定取得後に上限量の数値照合が必要なら、ウールヴ単独の自動Fangで
自己上限なしの最初の発動と、自己上限ありの後続発動を上限域で各3発から比較する。
手動Fangのみの優先1とは別の計測セットにする。ウールヴ由来の強化・闘心Lv・HP・
Fang攻防DOWNの有無も同時に保存し、同じ敵/装備でも無補正の単純比較とは扱わない。
交絡の補正量を独立に確定できなければ50%UPの実測確定は保留し、期限の観測だけを採用する。
境界や丸めが識別不能な場合だけ中間火力を1条件ずつ追加する（大量の漫然取得は不要）。

既存8本目は共存通常38行動で2発を確認したが、発動元の先後は不明。
ウールヴ＋無窮共存で1通常行動/2Fangのレスポンスを1件だけ保存し、
個々のhit、弱体/上限付与の前後を保持する。倍率確定用とは分離し、無窮等の強化交絡を記録する。
命中した1発目のDEF DOWNと上限UPが2発目へ適用されるか照合する。
発動元が区別できなければ先後は未確認のまま残す。

## 優先3: 弱体枠・命中・秒期限

Fangのみの攻防状態、既知片面の強い/弱い攻防DOWN→Fang、Fang→既知片面DOWNを
各1回から開始。別枠（両面/属性）共存は各1条件のみ追加し、同じ状態が何個残るか保存する。
攻DOWNは敵からの同じ攻撃、DEF DOWNは減衰前の同じ攻撃を比較。
初期3hit程度では成功率は推定しない。成功/失敗レスポンスを区別して保存するだけでよい。

180秒の直前/直後を同じ戦闘で1回ずつ保存する。途中の再発動を止め、実経過秒と残存状態を記録。
再命中は期限更新、失敗は既存効果保持かを各1例、取得できた場合だけ記録する。
複数枠の総計/下限を裏付けるデータが揃うまで、枠不明入力への自動加算は行わない。
