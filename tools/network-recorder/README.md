# GBF Network Recorder

グランブルーファンタジー(`game.granbluefantasy.jp`)のプレイ中に発生するネットワーク通信(XHR/Fetchのレスポンス、画像、スクリプト)を、ブラウザの開発者ツールのNetworkタブと同じ仕組みで**受動的に**記録しておくためのChrome拡張機能です。

## 設計方針(重要)

この拡張機能は **Chrome DevTools Protocol(`chrome.debugger` API)でタブにアタッチし、Chromeが既に受信したレスポンスを横から読み取るだけ** です。拡張機能自身が`game.granbluefantasy.jp`宛てに何らかのリクエストを発行することは一切ありません。記録されるのは、あくまでユーザー自身の画面操作(クリック・遷移)によって**ゲーム自身のJSが発行した**通信の結果です。DevToolsのNetworkタブを開いて記録しているのと技術的には同じことをしているだけ、という位置づけです。

記録を開始すると、Chromeの仕様により画面上部に「(拡張機能名)がこのブラウザをデバッグしています」という表示が出ます。これは仕様上避けられない(かつ意図された)ものです。何かが裏で動いていることの可視化として捉えてください。

## インストール方法(開発者モードで読み込み)

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をONにする
3. 「パッケージ化されていない拡張機能を読み込む」をクリックし、このフォルダ(`tools/network-recorder`)を選択

## 使い方

1. グラブルのタブ(`game.granbluefantasy.jp`)をアクティブにする
2. 拡張機能アイコンをクリックしてポップアップを開き、「記録開始」を押す
3. 画面上部にデバッグ中の表示が出るので確認する
4. 通常通りゲームをプレイ・画面遷移する(ジョブ画面を見る、キャラを見る、など)
5. 記録を止めたい時はポップアップの「記録停止」を押す
6. ポップアップの「記録内容を見る / エクスポート」から一覧・検索・エクスポートができる

エクスポートすると `gbf-network-recorder-export-{timestamp}.json` というファイルがダウンロードされます。このファイルをClaudeに渡せば、まとめて解析できます。

### URL検索と絞り込み結果のエクスポート

v0.4.0からURL検索欄は1つです。半角カンマ`,`で区切った検索語と、チェックした定型URLの**いずれか**を含むレコードを表示します（OR検索、大文字・小文字は区別しません）。前後の空白・空の検索語・重複は除きます。例: `/party/deck, start.json, result.json`。

チェックボックスは編成・出撃前編成/サポート召喚石・主人公ジョブ・主人公LB・キャラLB・耳飾り/指輪・キャラ詳細・武器詳細・バレット・マナベリ・秘器・盾・召喚石・戦闘開始・戦闘結果・大事なものの16項目です。入力欄と併用でき、チェックを外しても入力欄は変えません。定型URLは末尾の`/`を省いて両形式に対応し、主人公LBは`/zenith/bonus_list`としてキャラLBの`/npczenith/bonus_list`と区別します。`result.json`は`normal_attack_result.json`・`ability_result.json`・`summon_result.json`も含みます。

v0.4.1で「編成・主人公」に`/rest/quest/decks_info`を追加しました。出撃前の編成と選択したサポート召喚石を対象とし、提供記録では`supporter`に石のID・Lv・加護説明が含まれます。

- **全件をJSONでエクスポート**: 検索条件に関係なく、`apiCalls` と `assets` の全レコードを出力します。
- **絞り込み結果をエクスポート**: 入力欄とチェックボックスのOR検索条件を `apiCalls` と `assets` の両方に適用し、一致したレコードだけを出力します。未入力・未選択の場合は全件を出力します。一覧・件数表示・WebMCPの現在条件も同じ条件を参照します。

更新時は拡張機能の管理画面で拡張を再読み込みし、開いているビューアーも再読み込みしてください。保存済み記録の形式は変更しません。

編成・戦闘の再現用に必要に応じて入力欄へ追加する候補（2026-10-04のユーザー提供記録で確認）:

- `/rest/raid/get_hiddenweapon`: 戦闘中の秘器情報。`hiddenweapon_info.set_hidden_weapon`を含む。
- `/quest/create_quest`: 開始した戦闘のIDを含み、複数戦闘を収録した場合の対応付けに役立つ。

この2項目はチェックボックスには追加せず、カンマ入力で併用できます。`/npc/npc/`には装備アーティファクトのスキル情報・覚醒情報も含まれる例を確認しています。URLの照合は保存済みデータだけで行い、収集のためのゲーム操作はユーザーが行います。

検索ロジックの検証はこのフォルダで`npm test`、既存WebMCPの検証は`mcp-server/`で`node --test test/networkRecorderWebMcp.test.mjs`を実行します。テストには合成URLだけを使います。

### 個別コピー / 個別エクスポート(v0.2.0〜)

一覧の行をクリックして詳細を開くと、「コピー」「この項目をエクスポート」の2つのボタンが使えます。

- **コピー**: JSON/テキストのレスポンスは整形してクリップボードにテキストとしてコピーします。画像はPNGとしてクリップボードにコピーします(貼り付け対応アプリならそのまま貼り付け可能)。全件エクスポートより手軽にClaudeへの共有(チャットに直接貼り付け)ができます。
- **この項目をエクスポート**: そのレコード1件だけを、元の形式(JSON/HTML/PNG等)のファイルとして単体でダウンロードします。ファイル名はURLの末尾から自動生成されます。

### AIからの読み取り(WebMCP、v0.3.0〜)

WebMCPの命令型APIをサポートするブラウザでは、ビューアーに次の読み取り専用サイトツールを登録します。

- `get_recorder_state`: 記録済みAPIレスポンス・アセット件数と現在のURL絞り込み条件を取得
- `search_recorded_api_calls`: 記録済みAPIレスポンスをURL部分一致で検索し、本文を含まないメタデータを取得
- `get_recorded_api_call`: 検索結果の`recordId`を指定して、記録済みレスポンス1件を取得
- `find_recorded_weapon_skills`(v0.3.1〜): 10桁の武器マスターIDを指定し、武器詳細の`skillN.skill_id`または編成レスポンスの`skillN.id`からスキルID・名称・効果文だけを抽出

WebMCPツールはIndexedDBに保存済みのデータを読むだけで、記録の開始・停止、データ削除、ゲームへの通信は行いません。
検索結果のURLはクエリ文字列とフラグメントを除去して返します。本文取得は1件ずつ、テキスト最大200,000文字に制限し、
バイナリ本文は返しません。本文にはアカウント固有情報が含まれる可能性があるため、ローカル解析以外へ転載しないでください。
`find_recorded_weapon_skills`はレスポンス本文そのものを返さず、武器マスターIDとスキル情報だけに絞るため、skill_id確認にはこのツールを優先してください。同じレスポンス内に同一武器が複数本ある場合は1件にまとめ、`occurrenceCount`で本数を返します。

## データの保存先と内容

- 保存先はブラウザのIndexedDB(拡張機能のローカルストレージ)。サーバーには一切送信されません。
- `assets`(画像/JS/CSS): URLをキーに保存(同じURLへの再アクセスは上書きなので重複しない)
- `apiCalls`(XHR/Fetch/ドキュメント): 発生の都度、新規レコードとして保存(同じURLでも中身が変わりうるため)
- 画像はbase64エンコードして保存(バイナリも保持)

## 制約・注意点

- `chrome.debugger`は1タブにつき1クライアントしかアタッチできないため、DevToolsを別途開いている状態では記録を開始できません。
- サービスワーカー(background.js)がアイドルで一時停止しても、`chrome.debugger`のイベントリスナーは再度起動して受信を継続します(Manifest V3のイベント駆動の仕組み)。
- 記録対象ドメインは`game.granbluefantasy.jp`と`*.akamaized.net`(ゲームのアセットCDN)のみに絞っています。それ以外(広告・分析タグ等)は記録しません。
- v0.1.0時点でアイコン画像は未設定(Chromeのデフォルトアイコンで表示されます)。
- 画像コピーはPNG以外(JPEG等)の場合、内部でPNGに変換してからクリップボードに書き込みます(Clipboard APIがPNG以外を安定してサポートしないため)。
